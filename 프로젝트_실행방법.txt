영화 추천 프로젝트 실행 방법
작성일: 2026-10-06
프로젝트 위치: \NSMC

현재 영화 추천 데이터와 .venv 실행 환경이 준비되어 있습니다.
지금 PC에서는 1번과 2번 명령으로 서버를 실행하면 됩니다.
프론트 화면은 없으며, API 시험 화면에서 영화 제목으로 기능을 확인합니다.


1. PowerShell을 열고 프로젝트 폴더로 이동

아래 명령을 복사해서 실행합니다.

cd \NSMC


2. API 서버 실행

.\.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8000

화면에 다음 메시지가 나오면 서버가 실행된 것입니다.

Application startup complete.
Uvicorn running on http://127.0.0.1:8000

서버를 사용하는 동안 이 PowerShell 창을 열어 둡니다.
서버가 실행 중인 터미널에 다른 명령을 입력하지 않습니다.
다른 작업을 하려면 PowerShell 창을 하나 더 엽니다.


3. API 시험 화면 열기

브라우저 주소창에 아래 주소를 입력합니다.

http://127.0.0.1:8000/docs

영화 추천 백엔드 화면에서 [제목으로 조회] 항목을 찾습니다.
사용하려는 항목을 펼치고 [Try it out]을 누릅니다.
title에 정확한 영화 이름을 입력한 뒤 [Execute]를 누릅니다.
응답의 Code가 200이면 요청이 성공한 것입니다.

영화 상세 조회:
  GET /movies/detail
  title: 승부

영화 추천:
  GET /recommend
  title: 승부
  top_n: 5

리뷰 조회:
  GET /movies/reviews
  title: 서울의 봄
  order: high
  top_n: 5

order=high는 높은 실제 평점순, order=low는 낮은 실제 평점순입니다.
top_n은 1~20 사이의 정수입니다.
release_date와 director는 같은 제목의 작품을 구분할 때만 입력합니다.
일반 조회에서는 두 항목을 비워 둡니다.
개봉일을 입력할 때는 20250326처럼 YYYYMMDD 형식을 사용합니다.

영화 제목 일부를 검색하려면 GET /movies의 query 항목을 사용합니다.
movie_titles.txt에 원본 CSV의 영화명 216개가 한 줄씩 정리되어 있습니다.
현재 추천용 데이터에는 리뷰가 없는 두 작품을 제외한 214개 영화가 있습니다.
따라서 목록에 있어도 추천용 프로필이 없는 작품은 조회되지 않을 수 있습니다.

오류 응답의 의미:
  404: 현재 추천 데이터에서 제목/ID 또는 추가 조건에 맞는 작품을 찾지 못함.
  409: 같은 제목의 작품이 여러 개임. 응답의 후보를 보고 개봉일/감독을 추가.
  422: 제목이 비었거나 개수, 정렬 방향, 날짜 형식 등이 잘못됨.

기존 /movies/{movie_id}, /recommend/{movie_id},
/movies/{movie_id}/reviews 경로에도 영화 ID 또는 정확한 제목을 넣을 수 있습니다.
슬래시가 있는 제목은 [제목으로 조회]의 title 항목을 사용합니다.


4. 서버 종료

서버를 실행한 PowerShell 창에서 Ctrl+C를 누릅니다.
서버 종료 후에는 위의 API 주소로 접속할 수 없습니다.
다시 사용하려면 2번 명령을 실행합니다.


5. 터미널에서 서버 없이 추천·리뷰 확인

프로젝트 폴더의 PowerShell에서 실행합니다.

추천:
.\.venv\Scripts\python.exe recommender.py --title "승부" --top-n 5

높은 평점순 리뷰:
.\.venv\Scripts\python.exe review_service.py --title "서울의 봄" --order high --top-n 5

낮은 평점순 리뷰:
.\.venv\Scripts\python.exe review_service.py --title "서울의 봄" --order low --top-n 5

이 명령들은 저장된 정상 데이터를 읽습니다. API 서버가 실행 중일 필요는 없습니다.


6. 데이터를 처음 준비하거나 원본 CSV를 갱신한 경우

원본 파일은 프로젝트 루트의 Koreanmovie_review.csv입니다.
서버를 종료한 상태에서 다음 명령을 실행합니다.

.\.venv\Scripts\python.exe run_pipeline.py

이 명령은 원본 검사, 영화별 집계, TF-IDF/유사도 계산,
전체 영화의 추천/리뷰 검사, 정상 버전 저장을 순서대로 수행합니다.
결과는 artifacts\recommendation 아래에 버전별로 저장됩니다.
실패하면 기존 정상 버전은 유지됩니다.

이 과정은 리뷰의 TF-IDF 어휘/빈도 통계를 계산하는 데이터 준비입니다.
Ridge/LSTM 평점 예측 모델 학습은 실행하지 않습니다.
원본 CSV는 수정하지 않습니다.

준비가 완료되면 2번 명령으로 API 서버를 다시 시작합니다.
API는 시작할 때 데이터를 읽으므로 새 데이터 적용에는 재시작이 필요합니다.


7. 기능 검사

자동 테스트:
.\.venv\Scripts\python.exe -m unittest -v test_prepare_data test_pipeline

현재 저장 데이터의 전체 영화 추천/리뷰 검사:
.\.venv\Scripts\python.exe evaluate.py

실제 저장 데이터의 제목 검색·추천·리뷰 API 연결 검사:
.\.venv\Scripts\python.exe verify_backend.py

마지막 명령은 시험용 HTTP 클라이언트를 사용하므로 별도 API 서버를 실행하지 않아도 됩니다.
현재 구현에서 자동 테스트 33개가 통과했습니다.
이 검사는 기능의 정상 동작을 확인하며 추천 만족도를 입증하는 검사는 아닙니다.


8. 새 PC에서 실행 환경을 만드는 경우

Python 3.12 이상이 설치된 PC에서 PowerShell을 열고 실행합니다.
현재 프로젝트는 Python 3.12 환경에서 검증했습니다.
.venv 폴더는 다른 PC로 복사해서 재사용하지 말고 새로 만듭니다.

cd D:\JungPra\pythonpra\NSMC
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_pipeline.py

그 후 2번 명령으로 서버를 시작합니다.
다른 경로로 복사했다면 cd 명령의 경로를 실제 프로젝트 위치로 바꿉니다.
원본 CSV는 별도로 준비해야 합니다.

같은 Python 환경에서 검증 당시 패키지 버전을 재현하려면
requirements.txt 대신 requirements.lock.txt로 설치할 수 있습니다.


9. 실행이 안 될 때 확인할 순서

가. 파일을 찾을 수 없다는 메시지
   프로젝트 경로가 맞는지, .venv\Scripts\python.exe가 있는지 확인합니다.
   PowerShell의 Get-Location 명령으로 현재 위치를 볼 수 있습니다.

나. 추천 데이터가 없다는 메시지
   6번의 run_pipeline.py를 먼저 실행합니다.
   artifacts\recommendation\CURRENT.json과 해당 버전 폴더를 함께 유지합니다.

다. 포트 8000을 사용 중이라는 메시지
   이전에 실행한 서버 창이 있는지 확인하고, 그 창에서 Ctrl+C로 종료합니다.
   새 서버를 중복 실행하지 않습니다.

라. 브라우저에 접속되지 않음
   서버 PowerShell 창이 열려 있고 시작 완료 메시지가 있는지 확인합니다.
   주소가 http://127.0.0.1:8000/docs인지 확인합니다.

마. CSV 검사 실패 또는 메타데이터 충돌
   터미널의 중단 메시지에 표시된 컬럼/영화를 먼저 확인합니다.
   원본 값을 임의로 삭제하거나 같은 제목을 자동 병합하지 않습니다.

바. 패키지가 없다는 메시지
   .venv의 Python으로 requirements.txt를 설치했는지 확인합니다.
   다른 Python 대신 안내된 .\.venv\Scripts\python.exe를 사용합니다.


10. 참고 파일과 보관 자료

README.md: 실행 요약.
docs\BACKEND_GUIDE.md: 라이브러리 사용 이유, 데이터 흐름, 점수 계산.
docs\FUNCTIONS.md: 함수별 역할 설명.
docs\CURRENT_STATUS.md: 최신 구현·검증 상태.
docs\FILE_ORGANIZATION.md: 필요한 파일과 보관 파일의 위치.
archive\rating_prediction: 이전 평점 예측 실험. 현재 추천 서버에 필요하지 않음.

기존 train_model.py는 별도의 Ridge 학습 실험이므로 서버 실행을 위해 돌리지 않습니다.
