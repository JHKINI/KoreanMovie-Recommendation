# 영화 추천 프로젝트 핸드오프
작성일: 2026-10-01

## 1. 목적과 현재 합의
교수님 요구는 다른 학생들도 코드를 이해하고 따라 실행할 수 있는 교육용 프로젝트다.
사용자는 Python 기초, NumPy, pandas, FastAPI 학습 경험이 있다. 한국어로 단계별 설명을 제공하고 파일 위치, 실행 명령, 입력/출력 의미를 명확히 안내한다.
현재 우선 목표는 장르 후보 선정 + 메타데이터/리뷰 유사도 + 보정 평점 기반 영화 추천이다.
기존 TF-IDF + Ridge 평점 예측 실험은 유지한다. LSTM은 이후 확장이고 지금 바로 진행하지 않는다.

## 2. 집에서 가장 먼저 할 일
이 압축파일을 쓰기 가능한 폴더에 모두 풀고 해당 폴더를 새 작업 폴더로 연다.
패키지에는 원본 CSV, 기존 Python 코드 3개, 추천 참조 코드, 최신 PDF와 검증 결과가 포함되어 있다.
이 문서를 먼저 읽고 아래 시작 프롬프트를 새 대화에 전달한다.
기존 PC의 .codex/worktrees/ae42 경로를 재사용하지 않는다. 그 경로의 NSMC 폴더는 존재하지 않아 이전에 문제가 있었다.

Windows PowerShell 예시(압축을 푼 폴더에서 실행):
```powershell

.\.venv\Scripts\python.exe -m pip install -r requirements.txt

```
추천 참조 코드는 원본 CSV를 같은 폴더에서 읽고, 승부의 추천 목록과 서울의 봄의 높은/낮은 평점 리뷰를 출력한다.
검증 결과 verification.json을 같은 폴더에 쓰며 기존 JSON은 덮어쓴다. 원본 CSV는 수정하지 않는다.
패키지 버전은 고정하지 않았다. 참조 코드 검증 환경은 Python 3.12, NumPy 2.3.5, pandas 3.0.1이었다.
기존 사용자 학습 환경은 Python 3.14였고 정확한 학습 패키지 버전은 미확인이다.

## 4. 데이터 검사 결과
출처: https://www.kaggle.com/datasets/suminwang/korean-movie-review-data-30kbert
폴더명 NSMC지만 표준 NSMC 이진 감성 데이터셋이 아니다.
원본: 26,801행, 22컬럼, 영화명 기준 216개, 리뷰 결측 33행.
참조 추천 구현 정리 후: 26,768행, 214개 영화.
장르: 드라마 163, 코미디 34, 멜로/로맨스 15, 미상 2.
멜로/로맨스는 이 데이터에서 하나의 장르 이름이다. 슬래시로 임의 분리하지 않는다.
장르가 알려진 영화는 212개이며, 현재 장르 미상 영화는 추천 결과를 비운다.
프로필 결측: 감독 6, 상영구분 8, 장르/등급/관객 수/스크린 수 각 2개 영화.
검사한 7개 메타데이터는 같은 영화명 안에서 서로 다른 유효값 충돌이 없었다.
review_id는 리뷰 ID이지 영화 ID가 아니다.

리뷰가 없어 제외된 제목: 그 시절, 우리가 좋아했던 소녀 / 리향.
장르 미상 제목: 그 시절 우리가 좋아했던 소녀 / 초혼 다시 부르는 노래.
쉼표만 다른 제목이 있지만 동일 작품인지 확인 전 자동 병합하지 않는다.
고유 영화 ID가 없어 제목·개봉일 등을 확인하고 내부 ID를 부여하는 설계가 필요하다.

bert_label은 유효 행에서 0/1이고 pos_score > neg_score와 100% 일치했다.
평균은 기존 모델이 예측한 긍정 비율이지 사람의 감성 정답이 아니다.
rating은 실제 평점 0.5~5.0. 플랫폼별 척도 통일과 표본 편향은 미검증이다.

## 5. 합의된 파이프라인
[미리 준비]
원본 CSV → 영화 식별/결측/중복 검사 → 영화별 프로필 → 특징과 유사도 → 저장
프로필: 장르, 감독, 상영구분, 관람 등급, 관객 수, 스크린 수, 평균 평점, 유효 평점 수, 긍정 비율, 리뷰 텍스트.
평점 없는 리뷰도 텍스트에는 보존한다. v는 유효 평점 수, n은 리뷰 행 수로 구분한다.

[추천 요청]
제목 검색 → 영화 선택 → 같은/겹치는 장르 후보 → 자기 영화 제외
→ 메타데이터/리뷰 유사도와 감독 가산점 → 유사도 상위 최대 20개
→ 유사도와 보정 평점으로 정렬 → 최대 5개 추천 및 근거
→ 선택한 영화 리뷰를 높은/낮은 실제 평점순으로 조회
후보 부족 시 가능한 개수만 반환한다. 미등록 제목/잘못된 top_n은 명시적 오류로 처리한다.

## 6. 현재 참조 점수 설계
메타데이터는 원문 PDF의 sklearn 벡터 코드를 그대로 실행한 것이 아니다.
범주형: 상영구분/등급 일치 비율.
수치형: 관객/스크린 log1p, 중앙값 결측 보완, 평점/긍정 비율과 함께 min-max 정규화 후 1-평균 절대 차이.
meta = 0.5 * cat_sim + 0.5 * num_sim
리뷰: 문자 2~3그램, min_df=2, 최대 5,000특징, 로그 TF/smooth IDF/L2 정규화의 독립 NumPy 구현.
S = clip(0.4 * meta + 0.6 * text_sim + 0.05 * 감독일치, 0, 1)
감독 결측끼리는 일치로 보지 않는다. 범주형 미상끼리 일치하는 효과는 보완 검토 대상이다.

보정 평점:
B = (v * R + m * C) / (v + m)
Q = clip((B - 0.5) / 4.5, 0, 1)
final_score = 0.7 * S + 0.3 * Q
R: 영화 평균 평점, v: 유효 평점 수(고유 사용자 수 아님).
C: 전체 유효 평점 평균 약 3.0616, m: 초기값 20.
평가가 적으면 전체 평균 쪽으로, 많으면 원래 영화 평균 쪽으로 반영한다.
m은 최소 리뷰 수 필터가 아니다. 위 가중치와 m은 최적값으로 검증하지 않았다.
평점이 유사도와 최종 점수에 중복 반영되므로 평점을 meta에서 뺀 설정도 비교해야 한다.
IMDb 공식 참조: https://origin-help.imdb.com/article/imdb/featured-content/ratings-faq/G67Y87TFYYP6TWAV
Top 250 공식과 같은 형태이나 IMDb의 전체 비공개 평점 시스템을 재현한 것은 아니다.

## 7. 완료된 검증과 한계
- 원문 PDF 코드 검토: 숫자 결측 처리 부족, 벡터 0.4/0.6 결합을 유사도 40/60으로 해석하는 문제, 정렬 첫 행 제외 방식, API 입력 검증 부족을 지적했다.
- 원문 집계 후에도 영화는 214개였으며 문서의 216개 설명과 차이가 있었다.
- 참조 구현: 영화 214개에 대해 자기 영화 제외/장르 유지/중복 없음/최대 개수/유한 점수/내림차순 검사 통과.
- 리뷰 정렬: 214개 × 높은/낮은 평점 = 428경우 검사 통과.
- 미등록 영화와 top_n=0/21 오류, 텍스트 행 정렬과 유사도 대칭/대각선 검사 통과.
- PDF 렌더링과 내용 검증 완료. 공식 계산 예시도 확인했다.
- sklearn/FastAPI가 도구 환경에 없어 원문 전체 통합 실행은 하지 못했다. 추천 품질 향상이 입증된 것은 아니다.
- 추천 품질은 장르+보정 평점 기준과 비교하고 사람이 사례를 평가해야 한다.
- 크롤링, 저장된 추천 서비스, API, 웹 화면은 미구현이다.

## 8. 다음 구현 순서
처음부터 한꺼번에 API까지 구현하지 말고 아래 파일을 단계별로 만든다.
1. prepare_data.py: 입력 컬럼·평점 범위·결측·중복·영화 식별 보고서.
2. build_profiles.py: 영화별 정보 집계와 검사. 프로필 행과 리뷰 텍스트의 인덱스 일치 보장.
3. build_features.py: 메타데이터와 TF-IDF, 유사도 저장. 참조 구현과 sklearn 구현을 혼동하지 말 것.
4. recommender.py: 장르 후보/자기 제외/가산점/최종 순위/추천 이유.
5. review_service.py: 실제 리뷰 평점순 조회. 동점 원본 순서는 최신순이 아님.
6. evaluate.py: 동작 검사와 추천 품질 비교를 분리.
7. api.py: 검색, 추천, 리뷰 조회. 데이터/변환기는 요청마다 학습하지 않고 미리 로딩.
API 설계안: GET /movies?query= / GET /recommend/{movie_id}?top_n=5 / GET /movies/{movie_id}/reviews?order=high
데이터와 프로필/변환기/유사도는 같은 버전으로 관리한다.
크롤링은 추후 데이터 갱신 단계에 붙이며 모든 요청마다 후보 전체를 재수집하지 않는다.

## 9. 기존 평점 예측 실험
실제 review/rating으로 TF-IDF + Ridge 학습.
clean 26,432행 → ready 26,321행 → train 21,052 / test 5,269.
같은 리뷰가 train/test에 들어가지 않게 문구 그룹 분리했다.
TfidfVectorizer(analyzer='char', ngram_range=(1,3), min_df=3, max_features=50000, sublinear_tf=True)
Ridge(alpha=10, solver='lsqr')
사용자 실행: baseline MAE 0.8913, 모델 MAE 0.7464, 감소 약 16.3%.
튜닝 시 train 내부 그룹 검증 분리를 추가하고 TF-IDF는 학습 부분에만 fit한다.
추천 참조 집계와 정리 기준이 달라 행 수가 같을 필요는 없다.
기존 모델 재실행은 datachk.py → split_data.py → train_model.py 순서. 생성 CSV를 덮어쓰므로 새 실습 폴더에서 실행한다.
