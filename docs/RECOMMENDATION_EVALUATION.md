# 추천 설정 비교 보고서

기준일: 2026-10-11 · 데이터 버전 `20261006_010220_0c0fc253` · 기준 영화 212편(장르 정보가 있는 영화) · 추천 목록 길이 5

재현: `python evaluate_quality.py` (몇 초, TF-IDF를 다시 계산하지 않음). 상세 수치는 해당 버전 폴더의 `quality_report.json`.

> **이 보고서가 말하지 않는 것:** 사용자 만족도, 정확도, "어느 설정이 더 좋은가"의 답은 아닙니다.
> 추천 목록이 **어떤 성질**을 갖는지(안정성, 쏠림, 다양성, 커버리지)를 수치로 보여 줍니다.
> 만족도는 아래 "사람 평가"로만 확인할 수 있고, 아직 하지 않았습니다.

## 먼저 확인한 것

비교에 쓴 코드(행렬 연산)가 실제 추천 함수 `recommender.recommend()`와 같은 결과를 내는지 **214편 전체**에서 비교했고, 다른 영화는 0개였습니다. 같은 검사를 가상 데이터 테스트(`test_evaluate_quality.py`)에도 넣었습니다.

## 비교한 설정

| 이름 | 설명 |
|---|---|
| `current` | 현재 서비스 설정: 유사도 = 0.4×정보 + 0.6×리뷰 (+같은 감독 0.05), 최종 = 0.7×유사도 + 0.3×평점 |
| `text_only` / `meta_only` | 리뷰 유사도만 / 정보(메타데이터) 유사도만 |
| `no_quality` | 평점을 반영하지 않고 유사도만으로 정렬 |
| `quality_heavy` | 평점 비중을 0.6으로 (유사도 0.4) |
| `no_director_bonus` | 같은 감독 보너스 제거 |
| `metadata_without_rating` | 정보 유사도에서 평점 속성을 뺌 (문서에 적힌 "평점 이중 반영" 제거) |
| `hub_corrected` | **실험**: 같은 장르의 다른 영화들과 평균적으로 유난히 비슷한 영화의 유사도를 낮춤(강도 0.5, 가까운 10편의 평균 유사도 기준). 서비스에는 적용하지 않았고 이 보고서에서만 계산 |
| `baseline_rating` | 기준선: 같은 장르에서 보정 평점이 높은 순 |
| `random_same_genre` | 대조군: 같은 장르에서 무작위 (시드 고정) |

열 설명 (카탈로그 전체의 평균 리뷰 수는 125.1):
- **현재와 겹침**: 현재 설정의 추천 5편과 얼마나 같은지(자카드, 1이면 동일). 설정을 바꿨을 때 결과가 얼마나 흔들리는지 보여 줍니다.
- **평점 차이**: 추천된 영화의 보정 평점 평균에서 기준 영화의 보정 평점을 뺀 값.
- **평균 리뷰 수**: 추천된 영화의 리뷰 수 평균. 카탈로그 평균(125.1)보다 크면 리뷰가 많은 영화 쪽으로 쏠린다는 뜻입니다.
- **리뷰 유사도**: 기준 영화와 추천 영화의 리뷰 글 유사도. 리뷰 유사도를 쓰는 설정에 유리한 지표라 단독 해석은 위험합니다.
- **목록 내 다양성**: 한 목록의 5편끼리 서로 얼마나 다른지(1 − 리뷰 유사도의 평균).
- **커버리지**: 어떤 목록에든 한 번이라도 등장한 영화의 비율.
- **가장 많이 나온 영화**: 212개 목록 중 한 영화가 몇 번 등장했는지의 최댓값.

## 읽을 수 있는 것

1. **기준선(평점순)은 사실상 모든 영화에 같은 영화를 추천합니다.** "너와 나", "남으로 가는 길", "서울의 봄"이 212개 목록 중 162곳(76%)에 나오고 커버리지는 8.5%입니다. 평점만으로는 개인화가 안 된다는 것을 수치로 확인할 수 있습니다. 현재 설정은 커버리지 59%로 이보다 훨씬 다양합니다.
2. **현재 설정에도 쏠림이 있습니다.** "아침바다 갈매기는"이 54곳(25%), "해야 할 일"이 42곳, "수유천"이 36곳에 나옵니다. 리뷰 유사도만 쓰면 "아침바다 갈매기는"이 94곳(44%)까지 늘어, 리뷰 글 유사도가 특정 영화에 몰리는 경향이 보입니다. 이런 영화는 리뷰가 짧거나 일반적인 표현이 많을 가능성이 있지만, 원인은 확인하지 않았습니다.
3. **평점 반영은 추천의 평점을 올리고 커버리지를 낮춥니다.** 평점을 뺀 `no_quality`는 평점 차이가 +0.004, 커버리지가 0.783이고 현재는 +0.348, 0.590입니다. "평점이 높은 영화를 추천한다"는 의도는 지켜지지만 그 대가로 추천이 일부 영화에 모입니다. 비중 0.3이 적절한지는 이 표로는 알 수 없습니다.
4. **감독 보너스는 거의 영향이 없습니다.** 제거해도 겹침이 0.991이고, 추천된 영화 중 같은 감독의 영화는 1%입니다. 감독 정보가 있는 208편 중 같은 장르에서 같은 감독의 다른 작품이 있는 영화가 14편(홍상수 감독 4편 포함, 6쌍)뿐이라서, 이 데이터에서는 보너스가 사실상 쓰이지 않습니다. 영화 수가 늘면 달라질 수 있습니다.
5. **메타 유사도에서 평점을 빼도 크게 달라지지 않습니다.** 겹침 0.888. 문서에 적어 둔 "평점 이중 반영"은 존재하지만 결과에 미치는 영향은 크지 않았습니다.
6. **가중치는 결과를 크게 바꿉니다.** 리뷰만 쓰면 겹침이 0.247, 정보만 쓰면 0.443입니다. 지금의 0.4/0.6은 근거 없이 정한 초기값이므로, 사람 평가 없이는 더 낫다고 말할 수 없습니다.
7. **현재 설정의 목록 내 다양성(0.28)은 무작위(0.40)보다 낮습니다.** 비슷한 영화끼리 모으는 추천의 당연한 결과이고 결함은 아닙니다. 다만 5편이 서로 비슷하다는 점은 사용자에게 선택지가 좁게 느껴질 수 있습니다.

8. **쏠림 보정은 쏠림을 줄이는 방향으로 움직입니다(실험).** `hub_corrected`는 가장 많이 나온 영화가 54회에서 31회로, 커버리지가 0.590에서 0.679로, 목록 내 다양성이 0.280에서 0.335로 바뀌었고, 추천된 영화의 평균 리뷰 수는 169.6에서 145.5로 줄어 리뷰 많은 영화 쪽 쏠림도 약해졌습니다. 반면 추천의 보정 평점 우위(+0.352)는 그대로이고 기준 영화와의 리뷰 유사도는 0.664에서 0.651로 조금 낮아졌습니다. 다만 현재 추천과 겹치는 비율이 0.627이라 **목록이 3분의 1 이상 달라지므로**, 더 나은 추천인지는 사람 평가로 확인해야 합니다. 지표가 좋아졌다는 것과 사용자가 더 만족한다는 것은 다릅니다.

## 사람 평가 (아직 하지 않음)

만족도를 보려면 사람이 직접 비교해야 합니다. 블라인드 시트를 만들어 두었습니다.

1. [`docs/human_eval/human_eval_sheet.csv`](human_eval/human_eval_sheet.csv)를 평가자에게 공유합니다. 기준 영화 20편에 대해 두 목록(A/B)이 있고, **어느 쪽이 현재 설정이고 어느 쪽이 기준선(평점순)인지는 평가자에게 보이지 않습니다.**
2. 평가자는 "더 좋은 목록" 칸에 `A`, `B`, `비슷함` 중 하나를 적습니다. (영화를 모르면 비워 둡니다.)
3. **정답 키**는 `artifacts/human_eval/human_eval_key.csv`에 있습니다. 평가자에게 주지 마세요. (`artifacts/`는 git에 올라가지 않습니다.)
4. 여러 명이 채운 파일을 모아 집계합니다.

```powershell
.\.venv\Scripts\python.exe evaluate_quality.py --score 평가자1.csv 평가자2.csv
```

출력은 설정별 승수와 `비슷함` 개수입니다. 시트를 다시 만들면(`--sheet N`) 문항과 키가 모두 바뀌므로, 평가를 시작한 뒤에는 다시 만들지 마세요.

20문항 × 평가자 몇 명으로는 통계적으로 확실한 결론을 내기 어렵습니다. "기준선보다 확실히 나쁘지는 않다"를 확인하는 정도로 쓰는 것을 권합니다.
